A map for exploring possibilities.

ARES is a regional Mars route-planning prototype for NASA Space Apps 2026 — Founding Fathers. The original high-resolution Noctis Labyrinthus region is preserved, and region selection supports global MOLA when authentic NASA data is bundled with the deployed site.

Data used

  • NASA Planetary Data System · MGS MOLA MEGDR ↗

    Topography from NASA’s Mars Global Surveyor Mars Orbiter Laser Altimeter. Product MEGT00N180HB.IMG, version 2.0, 128 pixels/degree. The original high-resolution Noctis terrain and Viking imagery are stored in mars_map.bin, not in the Python server. Elevations are signed 16-bit metres above the MOLA areoid, not planetary radii. Pixel centres use planetocentric latitude and east-positive longitude.

    Original product label · Original elevation file (124 MB)
  • USGS / IAU Gazetteer of Planetary Nomenclature ↗

    Official named-feature centres inside the crop, extracted from the USGS Gazetteer of Planetary Nomenclature data. These are regional label anchors, not destinations certified for landing or driving. Your saved places are separate, personal labels.

  • NASA / JPL Mars Trek ↗

    Reference explorer supplied in the brief. No Mars Trek screenshots or 3D assets are repackaged. Our map is shaded directly from the embedded MOLA elevations; the brown palette is illustrative, not true-colour orbital photography.

V6 static hosting and planet-wide terrain

GitHub Pages runs this app directly in the browser, with Python routing via Pyodide. The Noctis area works using the supplied local binary. For global terrain, include real NASA MOLA MEGDR files (4 or 16 pixels per degree). The provided GitHub Pages Action can retrieve these original files at deployment, subject to NASA server availability. Selecting the whole planet is for coarse global visualization, not detailed rover hazard assessment. USGS/IAU named features come from the bundled gazetteer.

Three A* objectives

All searches use the full 433 × 433 grid and eight neighbours. Paths cannot cross diagonally between blocked cells. Both edge grade and local terrain slope are checked. Pins snap to native cells, within the current sampled elevation cell. Lines follow grid edges without cosmetic smoothing. Diagonals crossing a mesh triangle boundary are split at that boundary for distance, grade, energy and profile calculations.

  • Fastest: minimizes driving hours. Speed decreases with grade and DEM roughness.
  • Lowest energy: minimizes rolling work, uphill gravitational work and electronics consumption. Gravity is assumed to be 3.71 m/s²; no downhill regeneration is credited.
  • Gentlest terrain: minimizes distance weighted by slope and coarse DEM roughness; the slope ceiling is the lower of your setting and 15°. This is a safety and comfort proxy, not a measured accident probability.

Heuristics are lower bounds on their respective costs. The algorithm may return identical paths when objectives agree. It reports no route when constraints cannot be met; it never substitutes a straight line.

Model details & limits

Speed = level speed ÷ [1 + (grade/10°)² + 0.35 × roughness]. Energy (Wh) = mass × 3.71 × [rolling coefficient × surface distance + uphill rise] ÷ (3,600 × efficiency), plus electronics watts × driving hours; distances in this energy formula are metres. Safety cost = km × [1 + 5 × (local slope/10°)² + 2 × roughness]. Roughness is the absolute four-neighbour elevation Laplacian divided by 200 m, capped at 3.

Distances use a 3,396 km Mars sphere and latitude-aware edge lengths. Display projection is local equirectangular. 3D relief exaggeration affects only the view. Drive sols divide driving hours by your selected hours per sol; stops, charging and mission operations are excluded.

The original Noctis samples are about 460 m apart. Larger selected areas are much coarser. Some source cells are interpolated, and source-track gaps can be kilometres wide. Rock hazards, wheel-scale slopes, sand, soil bearing strength, traction and weather cannot be inferred reliably. This app is for comparing regional concepts, not commanding a rover.

Version 3 driving controls

WASD drives; Q/E turns in place without moving. Space brakes; C changes camera; P pauses; R resets the rover. In first person, drag the scene or use arrow keys to look around, and press L to centre. Automatic forward view is also available. Travel can be set from 1× to 100×, including decimal values. The simulation slope ceiling is independent of the route planner.

Every instruction waypoint is marked in the 3D world. The minimap shows only your next waypoint and the route trace. Passing within 150 m completes a waypoint; joining a later leg within 750 m skips earlier steps. Passing the end of a leg within this corridor also advances guidance. Progress never moves backward. Local minimap width can be set from 0.1 to 200 km.

New surface imagery

The sandbox includes a geographically cropped NASA Mars Trek Viking VIS global colour mosaic, layer Mars_Viking_MDIM21_ClrMosaic_global_232m (USGS MDIM 2.1). Level 7 WMTS tiles (about 326 m/pixel) were resampled to a 1024 × 1024 crop. It is embedded for offline use and aligned to the existing MOLA grid. Orbital imagery is regional, not wheel-scale detail. Procedural grain adds visual texture only; it does not affect elevation, obstacles, routes, or safety estimates. Daylight, sky and dust settings are illustrative.

Trip directions & rover sandbox

Start Trip lists exact collinear legs of your selected A* path. Bearings run clockwise from north; positive turn angles mean right, negative mean left. Elevation is in metres above the MOLA areoid. The upcoming turn occurs at the end of the listed leg. The last leg ends at the destination; the arrival entry has zero distance and no turn.

Drive Rover opens a new tab with an immutable copy of that route. Use W to accelerate, S to brake/reverse, A/D to steer, Space to brake, C to change camera, P to pause and R to reset. The on-screen keys support mouse and touch. Navigation automatically picks up later legs and accepts broad pass-by zones, as described above. The minimap, compass and off-route warning update from your position.

The sandbox uses true-scale MOLA relief (1×), a stylized six-wheel rover, arcade handling and selectable travel multipliers. The Viking orbital texture is real imagery; fine surface grain is decorative and is not hazard data. The rover stays on the DEM, stops at study-area boundaries and starts with the selected route's slope ceiling, then lets you change the driving ceiling independently. This is not validated vehicle dynamics. Plan times and energy estimates remain unchanged by gameplay.

WebGL provides the main renderer, with a lower-detail software 3D fallback. Switching away from the driving tab pauses it and clears held keys. V6 trip snapshots are stored in this browser and can be opened in a new rover-driving tab on the same published origin. Browser storage may be cleared at any time.

Run & storage

V6 runs as a static website on GitHub Pages. The published site needs no Python server. The browser loads Pyodide to execute the original routing algorithms; the JS bridge reads bundled terrain and site assets. Run python -m http.server locally only for development. GitHub Actions can download the optional authentic NASA global MOLA data during deployment. Hardware WebGL provides the full-resolution 3D mesh; browsers without WebGL use a software 3D renderer with a coarser display mesh. Routing always uses native-resolution data. Saved places stay in this browser’s local storage and are not synced. Changing the host or port creates a different browser storage origin.
